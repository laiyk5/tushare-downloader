## 管理规则

- 编号采用 BL-001 起的递增序号，分配后不改变、不复用；下一个编号为 BL-019。编号不编码分类、版本或状态。
- 状态仅有 unplanned（待规划）、planned（已计划，排队等待）、working（进行中）和 completed（已完成）。不维护“当前阶段”；状态流转与完成判定以 [工作流设计](../../design/workflow.md) 第 7 节为准。进行中不代表设计已经定稿，实施类事项不能仅凭设计文档标为完成。
- 只有定稿设计可实施。软件目标版本未确定就标为未定，设计版本不自动决定软件版本。
- 分类独立于状态：开发流程、文档与升级、CLI 与可观测性、数据存储与兼容性、数据集扩展。
- 每项维护编号、标题、分类、状态、目标／完成版本、需求范围、验收条件及设计／证据链接。未定义的验收条件明确标为待设计，不虚构已验收标准。
- 状态变化时移动正文并更新本索引链接，保留编号；不得复制同一正文到多个状态文件。引用本页锚点，不依赖状态文件路径。
- 分阶段事项分别编号并关联，避免“部分完成”掩盖后续缺口。退回待规划时保留原因；撤销、重复合并的事项也保留编号和说明，不假称验收完成。
- 本地维护即可；更新 backlog 不自动推送、创建 PR 或触发 GitHub workflow。
