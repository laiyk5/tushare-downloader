2. 同一版本的产物有明确归集入口，能准确定位每个 patch 的记录与证据，不发生覆盖或版本混淆。
3. 迁移前后产物完整、历史证据不变，站内链接、导航和相关脚本有效；旧公开链接有明确兼容处理。
4. 文档说明后续新增产物的放置规则，本地严格构建与目录/引用核对通过。

## BL-012 · 数据集 Inspect 能力 {#bl-012}

- 分类：CLI 与可观测性
- 状态：进行中
- 目标版本：v0.4.0（revision 2 定稿）
- 关联设计／证据：[Inspect 草案](../../design/inspect.md)，测试条件 IN01–IN09；已定稿，开始测试先行实施

- [ ] 设计面向本地数据状态的查询能力，补足当前 list 仅列出受支持 API 的不足。
  - 基础范围：各数据集占用空间、最新数据时间（适用时）、上一次拉取时间。
  - 明确空间是否包含索引等对象；区分数据时间、请求尝试时间和成功提交时间，避免将失败请求或跳过当作成功更新。
  - 对空表、未初始化、快照接口无数据日期等情况提供准确表达；明确读取权限、查询成本与大库性能边界。
  - 不引入任务管理或后台状态服务；命令、选项、布局与现有 list 的关系留待设计。
  - 按数据块可视化覆盖情况拆分为 [BL-016](index.md#bl-016)，不纳入基础 Inspect 的默认实施范围。

### 验收条件

1. 用户能查询各数据集的基础状态，字段定义清晰，并正确呈现不适用或尚无记录的情况。
2. 查询不发起数据下载、不修改业务数据；空间和时间信息可与数据库事实对照。
3. 明确观察到的数据范围不等于业务完整性；复杂覆盖可视化在独立设计评审后实施。

## BL-013 · 用户数据访问与稳定 schema {#bl-013}

- 分类：数据存储与兼容性
- 状态：进行中
- 目标版本：v0.4.0（revision 2 定稿）
- 关联设计／证据：[用户数据访问草案](../../design/data-access.md)及其 [schema 子章节](../../design/schema-contract.md)，测试条件 DA01–DA08、SC01–SC08；已定稿，开始测试先行实施

- [ ] 设计用户读取数据的标准方式，schema 契约作为其中一部分。
  - 定义只读账号的有效权限、既有用户补权、未来新增表权限，以及标准 SQL 入口。
  - 明确 stale 读取、一致性及数据内容修正边界；评估普通视图与物化视图，本版提供用户维护的可选普通视图示例，不自动创建产品视图。
  - 为下载落库的数据提供稳定、可查询并可追溯的版本化 schema 契约。
  - 明确字段名、类型、可空性、唯一键、原始字段与下载器附加字段，以及供下游使用的稳定边界。
  - 优先保持已有表结构稳定；说明 API 新增、兼容字段扩展和破坏性变更各自如何分类与处理。
  - 定义 schema 版本粒度，以及它与软件版本、设计版本和现有 schema_version/spec_version 的关系，避免重复引入含义相近的版本机制。
  - 用户应能查询当前库/数据集的 schema 版本，得知版本间结构变化，并找到对应迁移说明；具体查询和变更通知入口待设计。
  - 与升级指南和 Inspect 协调，考虑下游 SQL、Excel、研究脚本等已有依赖。

### 验收条件

1. 每个支持的数据集有与实际数据库一致的结构契约和版本标识。
2. 表结构变化可追溯至变更记录、兼容性说明和升级路径；不会静默改变契约。
3. 新旧 schema 的识别、兼容性校验及需要迁移时的行为有测试，版本策略不等同于每次软件发布都升级所有表。
4. 只读账号可按标准 SQL 读取且实际写操作被拒绝；可选视图、升级补权和读取一致性有独立数据库证据，不能只交付字段表。
