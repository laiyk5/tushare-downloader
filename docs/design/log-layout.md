# 按命令组织日志目录

归属 [当前设计](index.md)，对应 [BL-010](../development/backlog/index.md#bl-010)。路径规范继承既有定稿，准备失败事件为 revision 7 定稿；整体版本状态见设计入口，不表示草案已实施。设计目标是便于按命令查找日志；不新增任务管理、日志查询命令或跨分片监看服务。

## 1. 路径契约

LOG_DIR 继续表示日志根目录，默认 `./logs`，相对路径仍相对调用时的工作目录。不增加配置键或 CLI 开关。

```text
logs/
├── fetch/<run>.jsonl
├── fetch/<run>.1.jsonl
├── refresh/<run>.jsonl
└── update/<run>.jsonl
reports/<run>/report.md
```

上例中的 `<run>` 是执行标识占位值，各调用使用不同标识；一次调用的日志首片、后续分片与报告使用同一标识。保持现有 UTC 时间加随机后缀格式，分片序号规则不变。报告目录不随命令增加层级。

| 调用 | 日志位置 |
| --- | --- |
| fetch / f，包括 --dry-run | LOG_DIR/fetch/<run>.jsonl |
| refresh，包括 --dry-run | LOG_DIR/refresh/<run>.jsonl |
| update / u，包括 --dry-run | LOG_DIR/update/<run>.jsonl |
| list / ls、init-db / init、clean、help、version | 保持当前行为，不为本次目录调整新增文件日志或空命令目录 |
| 参数或配置校验失败，尚未建立 Reporter | 保持原错误输出，不伪造日志路径 |

规范命令名由 CLI 的既有命令分派提供；不能用原始输入、API 名、任意参数或未来未验证的命令拼接目录。允许的生产目录名明确限定为 fetch、refresh、update。不同 API 的同类命令归入同一目录，API 信息继续记录在日志事件中。

## 2. 创建、失败和输出

按需创建当前命令子目录，不预建其他命令目录。日志创建、启动事件写入成功后立即显示实际路径，早于数据库检查、日历和远端请求。Rich/plain 及 quiet/normal/verbose 共用同一路径规则，不能静默退回根目录或临时目录。

目录路径被普通文件占用、权限拒绝、日志创建或首条写入失败时，沿用输出故障的非零退出规则（退出 1），不开始数据库或网络工作；报告和日志仍只展示实际成功建立的产物。可能留下空目录或不完整报告目录，不为此次调整增加自动递归清理。

不同调用的执行标识彼此隔离。目录已存在可以复用；执行产物发生同名冲突时不得截断、覆盖或追加到旧调用。冲突明确失败，不新增恢复协议。实现可优先沿用现有报告目录的独占创建来检测相同标识，并检查日志文件独占创建；测试必须覆盖“只有孤立日志、没有同名报告目录”的情况。

轮转分片始终写入同一命令目录，不改变现有 JSONL 字段、级别筛选、分片保留和日志故障语义。最终报告列出全部实际分片路径，用户仍能从启动输出复制路径监看当前文件。跨分片自动跟随属于 BL-007，不在本项实现。

## 3. 旧文件与兼容性

升级不扫描、移动、删除或重写旧的 LOG_DIR/<run>.jsonl 及其分片。旧报告中的路径仍指向原位置；新调用只写新目录。系统没有统一日志读取服务，因此不新增“兼容读取器”；用户可按原路径读取历史文件。

依赖根目录通配符的用户脚本需要调整，这是用户可见的路径变化，必须进入升级指南。推荐使用启动输出及报告中给出的真实路径；Bash 示例明确命令子目录，不承诺自动合并日志或跟随轮转。

默认 `logs/` 的忽略规则已覆盖子目录，不扩大 .gitignore。自定义根目录仍由用户配置忽略规则。配置参考和 .env.example 的英文注释说明根目录用途，默认值不改；不重写本地 .env。

## 4. 实现边界与文档

路径选择集中在 Reporter 建立阶段，复用现有日志 handler 和轮转机制，不在各 API 复制处理。所有 CLI 入口先提供规范命令名。更新测试中真正依赖路径的断言，不因目录变化放宽 JSONL、输出顺序或写入结果验证。

实施时同步英文配置参考、下载指南、升级指南及实际 CLI 示例。已归档证据保留历史路径。早期 HTML demo 与静态报告示例若仍展示旧路径，必须在其入口明确标注模拟基线与路径差异，不将旧资产描述为新布局实证。

## 5. 先于实现确定的测试条件

以下 LG 编号是条件标识，不是已通过结论。

| 编号 | 输入或故障 | 预期及验证方式 |
| --- | --- | --- |
| LG01 | 三个命令、f/u 缩写、两个不同 API | 命令全名决定目录，缩写与全名归属相同，API 不增加目录层级；CLI/Reporter 测试 |
| LG02 | 默认根目录、自定义绝对路径、带空格相对路径，不同 cwd | 保留根目录配置优先级及 cwd 语义；实际文件与显示路径一致 |
| LG03 | 三个命令 dry-run；help/version/list/init-db/clean；参数错误 | dry-run 使用对应目录，其他调用不因本项新增日志目录；隔离依赖检查 |
| LG04 | 六种显示组合、初始化正常 | 启动日志事件落盘后显示路径，显示早于 DB/日历/HTTP；quiet 不隐藏路径；报告位置不变 |
| LG05 | 降低轮转阈值触发多片 | 片名、同目录归属、JSONL 可解析、事件不丢失；报告枚举全部实际文件 |
| LG06 | 目录被文件占用、权限/创建/首写失败 | 退出 1，无 DB/HTTP 调用，无虚假成功路径，无备用目录；故障注入 |
| LG07 | 两个独立调用并行创建、强制相同标识、孤立同名日志 | 正常独立文件；碰撞失败，旧文件字节不变；不以数据库写锁测试代替日志创建测试 |
| LG08 | 预先放置旧根目录日志、分片、旧报告 | 新调用不修改旧文件；旧报告路径仍有效，新文件只在命令子目录 |
| LG09 | 报告、配置注释、忽略规则、旧 demo 说明 | 文档与实际路径一致；logs 子目录被忽略，示例和源码仍可跟踪；严格构建及人工检查 |

按正常、旧产物、冲突、I/O 故障划分等价类；先编写失败测试，再改路径实现。只因输出路径改变不能重写下载语义的期望。沿用现有日志故障、轮转及显示模式测试并补齐路径条件，不要求为每个编号另建测试文件。

## 6. 与版本产物整理的边界

本页调整用户运行日志，BL-017 调整仓库内选定的版本证据，两者不共用迁移机制。旧运行日志必须保留原位置；选入文档的历史日志／终端附件按 [版本产物目录](development-layout.md) 保持原字节移动，不能为了符合新日志布局改写其历史内容。

## revision 3：setup 事件日志

setup 采用 LOG_DIR/setup/<UTC>-<random>.jsonl，TUI/headless 共用事件协议，详见 [主契约第 8 节](database-setup.md)。它不使用下载 Reporter，也不生成 report.md；帮助/版本不创建日志。新增日志不是持久执行任务，不能据此 resume 或重放数据库动作。下载日志布局及历史文件规则不变。

## 准备失败事件与安全描述 {#preparation-errors}

本节为 revision 7 定稿规范，待实施。

实现建议：在现有下载准备异常出口构造一次小型、白名单化的错误描述，共用于终端、report.md 和 JSONL；复用已有脱敏器，不建设通用错误框架。

- 已知错误以稳定 code、英文 message、可选英文 hint 表达。本轮仅新增一个已知原因专用映射和一个通用后备；不按全部异常类型扩展错误目录。专用 code 为 `missing_tushare_token`：
  - message：`TUSHARE_TOKEN is not configured. No remote requests started.`
  - hint：`Set TUSHARE_TOKEN in your selected configuration file or environment, then retry.`
- 报告呈现遵循 [帮助与报告契约](help-and-reports.md#preparation-report)，三个出口使用本节同一安全描述。
- 日志增加 `preparation_failed` ERROR 事件，包含 code/message/hint、api、command 和既有时间／运行关联字段。字段为兼容增补；quiet 不影响文件事件；现有合法 LOG_LEVEL（DEBUG/INFO/WARNING/ERROR）均应保留 ERROR。不扩大 LOG_LEVEL 取值、不改变其他级别过滤规则。
- 已知可安全描述的错误用允许的文案映射；未知错误只输出类别、通用说明和查日志指引，不能直接持久化 str(exception)、连接串、响应体、Token、密码或完整环境变量。通用后备 code 为 `preparation_error`；message 使用固定的安全阶段说明，hint 指向配置／连接／日历检查指南，不把未写入日志的细节承诺成“见日志可查”。类别只接受程序侧类别标识，不序列化异常对象。该约束同样适用于 verbose：可保留安全调用位置，不输出原始异常消息、链式异常秘密或 locals；不可因展开 traceback 绕过白名单。现有安全诊断规则保持。
- 每次准备失败只记录一次原始失败事件；日志或报告本身写入失败时，向 stderr 给出安全降级说明及已知结果，保持非零退出，不递归写错误或重做请求。不保证 I/O 失败时仍能落盘。
- 保留现有退出码、原子性与已提交结果。发生在配置加载／参数解析阶段、尚无日志上下文的错误不强行创建运行文件。

### 阶段与证据边界

仅处理下载命令已有 reporter、尚未进入数据块执行时的失败，包括现有日历准备失败出口；共用描述和事件，不重复追加另一条 preparation_failed。既有 invocation_finished 终结事件可保留，终结事件不是第二条错误事件。

`No remote requests started.` 只用于已确定任何远端尝试均为零的缺 Token 场景；日历失败可能已有 calendar HTTP attempts，必须保留实际次数，并说明 `No data requests started.`。未知计数明确 unknown，不能填 0。空块结果不等于零远端尝试。执行阶段失败、KeyboardInterrupt 和提交未知仍走原有路径，不改归类、不丢结果。

已有报告采用安全原因；本轮不重构其他命令的 guarded 异常体系、不改变 API 重试规则。日志初始化失败没有日志文件保证；reporter 已存在时也仅在可写出口保存。
