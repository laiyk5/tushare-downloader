# 数据库设置交互


**v0.4.0 / revision 6 定稿。** 顺序问答和 Rich 配色沿用已实施设计；迁移在相同 Review/确认/执行流程内完成，不另建界面。共用规则见 [主契约](database-setup.md)及 [迁移契约](database-migrations.md)。

## 1. 主流程

读取配置 → 自动检查 → 按需补充信息 → 展示差异并确认 → 执行 → 验证 → 按需保存配置。用户不选择“初始化还是升级”。

- 无连接配置：询问服务器 host/port/SSL、目标库和账号，保留已有部分值。必要时获取临时管理连接，通过已存在的维护库检查目标；目标不存在不是“服务器连接失败”。
- 有配置：自动进行有界只读检查。Ready 且配置未改，打印就绪摘要后直接退出，不再强制经过菜单或索要 reader 密码。
- Unknown：说明连接/认证/权限/超时原因，选择修改相关字段、重试或退出。每次重试由用户主动发起，不无限循环。
- Needs configuration：列出已证实缺项，收集必要凭据，展示创建/初始化/补表/补权计划。
- Unsupported：说明原因和人工处理路线，允许另选连接或退出，禁止猜测修复。
- Migration needed：展示完整有序升级链、逐步版本与影响；输入真实目标库名确认后执行。失败保留已提交步骤，Recheck and review 从实际版本生成剩余计划；不再引导另一个命令。具体授权与状态见迁移契约。

新连接使用交互专属 `setup --new`。已有流程的修改菜单也可选择 New connection，但执行中不可切换。它创建独立内存草稿，保留原文件和原库；目标库存在时检查复用，不强制建新库。显式 -c 路径作为用户选定的配置来源；--new 不直接覆盖该来源，仍先选择另存目标并确认。旧连接的秘密不继承。本次会话的显式输入优先于启动时环境/文件值；保存后的日常命令仍按环境覆盖文件，预览必须指出这种差异。无旧配置时默认保存至选定的 .env；从已有配置新建连接默认另存未占用的 .env.new，具体并发规则继承主契约。

### 配置来源与会话值 {#session-configuration}

普通启动先计算逐键环境 > 指定文件 > 默认值；默认值本身不构成已配置事实。完整环境配置可直接自动检查，不重复询问。用户明确编辑后，本次会话值 > 启动时环境 > 文件 > 默认值；检查、计划、执行、验证必须使用同一会话快照，不在阶段间重读环境覆盖用户编辑。不会修改父 shell。

--new 始终进入新连接问答，即使 PG* 完整也不自动检查旧目标。非秘密值可作为明确标注来源的默认建议，用户确认后才进入新目标检查；不复制原文件/环境中的 PGPASSWORD，不让驱动隐式继承旧身份。仍可使用与选定身份匹配的 .pgpass 等认证方式。

| 启动情况 | 来源与默认保存目标 |
| --- | --- |
| 普通 setup，默认 .env 不存在 | 环境完整则检查；否则问缺项；有新增设置才提供保存 .env |
| 普通 setup -c new.env，文件不存在 | 将该明确路径作为拟保存目标；环境完整仍可检查，无修改不自动创建文件；需要保存时独立确认 |
| setup --new -c existing.env，文件存在 | 只读来源，默认另存同目录未占用 .env.new；原文件不自动覆盖 |
| setup --new -c new.env，文件不存在 | 显式路径就是拟保存目标，不追加 .new；先问答再检查；保存时拒绝并发覆盖 |
| setup --new，未指定 -c | 有旧配置时建议未占用 .env.new；无旧配置时 .env |
| 显式配置不可读或语法歧义 | 不自动忽略并连接默认服务器；说明问题，允许改选配置路径或退出 2；源文件保持不变 |

保存目标只是提议，不是自动写入授权。选择另存现有文件必须重新读取其快照、预览差异并明确确认，不能沿用旧文件授权。headless 的 -c 不存在仍直接退出 2。

## 2. 顺序问答与编号编辑

输出追加到普通终端，不使用备用屏幕、Widget、焦点管理、全局快捷键或后台表单刷新。输入是当前行的标准终端输入，不引入浏览器式表单。浏览器 Demo 的按钮是文字选项的可点击替身。

每组问题结束显示摘要：`[C] Continue  [E] Edit settings  [Q] Quit`。编辑菜单按编号列出 Host、Port、SSL mode、Database、Writer、Reader，以及按需出现的维护库和凭据操作；选一个字段修改后回到摘要，其他输入保留。所有字段不能只靠反复 Tab 到达。

普通字段 Enter 保留已显示的默认值；没有有效默认值时继续询问该字段。格式错误只重问当前字段并说明原因。在普通问答中不解释全局 b/q 等字符串，以免它们与合法库名、用户名或密码冲突；返回与退出通过显式菜单，随时 Ctrl+C 中断。选择菜单 Enter 默认安全返回/不执行；目标名确认不提供自动填写的默认值。

任一影响目标、角色或权限的字段变化撤销旧计划和确认，重新检查后再预览。一次只处理当前输入或当前有界检查，不在等待输入时并发查询；无需 generation、迟到结果或输入焦点恢复机制。执行中不接受目标编辑，Ctrl+C 按主契约停止后续动作并报告部分结果。

## 3. 凭据与后果

- 尽量使用已有有效认证。只有需要管理能力时才请求管理员与维护库；不能要求用户先创建 writer 或目标数据库。
- 新账号密码隐藏输入并重复确认；不一致只重问该账号。不能把空密码当作默认许可创建；无密码创建必须通过独立高级选项明确确认。
- 已有账号采用 Keep / Replace for this session / Clear temporary override 菜单。替换只验证身份，不重设数据库密码；清除临时覆盖不等于删除文件中的旧密码，后者在保存预览中单独确认。
- 密码没有导航保留字。管理员和 reader 密码从不保存；writer 保存独立 opt-in，默认否。
- 输入管理员信息前说明只在本次使用；确认复用/创建角色前说明角色为集群共享。写前说明影响对象和本次权限范围。
- 改端点或身份丢弃不再适用的临时凭据；日志、历史摘要和错误不显示秘密或密码长度。

## 4. 差异、执行与恢复

确认前显示 Target、实际 Before → After、Action 和必要后果。未知事实不能显示为不存在。默认只列变化项；详细模式可增加无变化项，关键影响不受 -q 抑制。

`Apply` 前精确输入目标数据库名。确认后仍重查前置条件；状态改变时停止并重新计划，不扩大授权。分步输出 Running / Completed / Failed / Unknown / Not attempted；无精确依据不显示 ETA。无需持续 Live 重绘或动画。

失败后保留成功动作。重新检查只计算剩余动作；认证失败仅修正凭据后重验，不重放已完成写入；保存失败仅重试文件保存。已提交对象不能因退出自动删除。

数据库就绪后，有新增或修改配置才提供保存预览，显示文件旧值、环境有效值、拟写值和来源。保存单独确认；拒绝保存仍报告数据库 Ready 和 Configuration: Not saved。临时验证成功但日常 writer 凭据未配置时，明确提示下一次连接还需要认证。无修改不写文件。文件安全、冲突检测、0600 和原子发布继承主契约。

## 5. 颜色、布局和模式

| 信息 | 视觉 | 必须保留的文本线索 |
| --- | --- | --- |
| 命令、当前阶段、当前问题 | 蓝色／终端 cyan | 命令或阶段标题 |
| 参数值、用户确认的非秘密值 | 紫色 | 字段名和值 |
| 成功、就绪 | 绿色 | Completed / Ready，必要时 ✓ |
| 尚未执行的变更、风险或部分完成 | 橙色／终端 yellow | Proposed changes / Warning / Incomplete |
| 失败、不可继续 | 红色 | Failed / Unsupported 与原因 |
| 日志路径、来源和辅助说明 | 灰色弱化 | Log / Source；保证可读对比度 |

仅突出标题、状态和关键值，不把整段正文染色。取消不显示为成功；配置未保存与数据库成功分别呈现。采用 Rich 标准语义色，适应终端主题，不承诺网页 RGB 与终端完全一致。不把用户输入解析成 Rich markup；端点/名称中的终端控制字符需安全显示。全流程英文输出，设计说明保持中文。

每组问题与计划之间空行分隔。80/120 列可紧凑表格；40 列使用逐项 Before / After，不截断名称、路径、动作后果。普通终端滚动历史就是回看方式，不设内部滚动区域或最小窗口阻断；更窄宽度尽力换行，不承诺所有终端输入编辑行为。窗口改变只影响后续输出，不清除历史。

`--plain` / 配置 PLAIN=true 使用同一问答和检查流程，仅去掉颜色、装饰和控制序列；不是第二套向导。TERM=dumb 使用纯文字。同一控制台的 -q/-v 不隐藏必需问题、目标、影响、确认、失败和日志路径。NO_COLOR 禁用颜色，不改变授权。

交互要求 stdin/stdout 为 TTY；非 TTY 退出 2 并提示 --headless，绝不自动 apply。headless 不提问、不写 .env，接受 plain。--new 与 --headless 不兼容，写前参数错误 2；--apply/--credentials-file 仍只属于 headless。help 不启动检查、日志或界面。

## 6. 验收条件

编号与历史保持关联，但 revision 3 的焦点/页面测试不是本版证据。UI01–UI04 在本 revision 明确替换为：

| 编号 | 条件 | 通过标准 |
| --- | --- | --- |
| UI01 | 首次配置、Ready、--new、编号修改与默认值 | 不要求预建目标/账号；Ready 直接结束；编辑保留其他值；菜单回退安全；输入只影响选定字段 |
| UI02 | 连接错误、编辑后重查、计划失效、执行中断 | 无无穷自动重试；旧计划不能执行；单次有界操作；取消停止后续动作，部分结果保留 |
| UI03 | Rich/plain/NO_COLOR/TERM=dumb，40/80/120 列及长值 | 相同业务决定；去色后状态可辨；无关键截断；无备用屏幕或光标重绘；控制字符与 markup 不被执行 |
| UI04 | 隐藏密码、目标确认、EOF/Ctrl+C、冷启动、错误退出 | 密码不泄漏；未确认零写入；恢复终端回显；内部异常非零；独立新进程首个检查可运行 |

EOF/Ctrl+C 退出 130，已经发生的动作仍报告。正常流程尚未写入时主动取消为 0；未解决的 Unknown 后退出为 1，Unsupported 后退出为 5，锁冲突为 3，输入解析错误为 2。部分失败后退出为 1（用户中断为 130）。成功重查/恢复后按最终状态返回 0，不把已解决的历史错误永久带入退出码。数据库就绪后主动拒绝保存为 0，明确 Configuration: Not saved；保存失败尚未解决时退出为 1。自动输入测试必须断言正确提示、分支、退出码和无额外写入，不只断言输出包含字符串。

最小终端验证由开发者／代理负责：在 WSL/Linux Python 中通过真实 PTY、自动输入及输出检查完成首次创建、已有配置 Ready、编辑后保存、失败重查四条路径；已有有效证据直接复用。密码隐藏、Ctrl+C 与终端回显恢复须用终端状态及捕获输出验证，不能仅用 CliRunner 或截图推断。40/80/120 列及 plain 检查沿用既有代表场景，不做全排列、不按尺寸重建数据库。Windows Terminal 的宿主显示效果可由用户自愿反馈；不要求用户重复机械清单，不将主观反馈设为默认完成门槛。代理缺少工具时记录具体限制，不以“需要人类能力”为由转交整份清单。

复用未变数据库核心的真实认证/权限/事务证据时，标明来源 SHA、未变范围与新增适配测试；不得把原 651 项通过结论直接改成 revision 4 通过。优先测试分支与失败边界，稳定候选再做一次完整必要回归。
