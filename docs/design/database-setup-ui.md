# 数据库设置界面

归属 v0.4.0 / revision 3 定稿，BL-018；与[数据库设置向导](database-setup.md)共同定义体验。使用 Textual 构建全屏交互，Click 保留命令入口，下载输出继续使用 Rich。新增界面尚未实现；[可交互 Demo](database-setup-demo.md)是浏览器模拟，不是 Textual 运行证据。

## 1. 目标与布局

用户无需选择初始化或迁移类型。进入后自动检查已有配置；无配置直接编辑。每屏保持标题、步骤导航、主要内容、动作和键盘提示；只刷新变更区域，不不断追加旧页面。

| 区域 | 内容与作用 |
| --- | --- |
| 顶栏 | setup、目标端点、检查/执行状态；状态有文字，不只靠颜色 |
| 左导航 | Connection / Access / Review / Result；可以返回已到达页面，未来步骤按条件禁用 |
| 内容区 | 原位表单、检查摘要、差异表或结果；超长内容区内部滚动 |
| 操作区 | 本页主动作一个；返回、取消、新连接等次动作明确分开 |
| 底栏 | Tab/Shift+Tab、Enter、Esc、F1 帮助提示；未写入或部分提交状态 |

宽屏连接页为左侧表单、右侧检查摘要。紧凑屏改为上下排列，导航改为顶部页签；再窄时每行一个字段、差异表变为逐项 Before/After，不横向截断关键名称与路径。40/80/120 列均可操作，低高度允许内容滚动且操作可到达，不依赖鼠标。

## 2. 页面契约

### Connection

显示配置来源、host/port/SSL、目标库、writer 及凭据来源。用户直接聚焦字段编辑。无配置或新连接需要管理连接时在 Access 收集，不能假定目标库或 writer 已存在；Connection 的检查允许只得到“待提供管理连接”的结果，不冒称服务器已验证。

已有配置自动检查；Ready 提供 Finish / New connection / Edit and recheck，缺项提供 Continue configuration；失败明确 Unknown，提供修正及重查。新连接保留旧配置，默认另一文件，说明目标可能复用现有库。

### Access

只展示计划所需信息。需要管理权限才显示管理员和维护库；writer 已有有效凭据时保留，不重复索取；缺 reader 才显示创建所需名称、密码和确认。已有 reader 因补权或主动验证需要登录、且无可用认证方式时，也在本页收集验证凭据，但不显示新密码重复确认，不修改该角色密码；写计划开始前收集已知必要凭据。已有 reader 因补权或主动验证需要登录、且无可用认证方式时，也在本页收集验证凭据，但不显示新密码重复确认，不修改该角色密码；写计划开始前收集已知必要凭据。使用 Textual Input 的隐藏输入，不把密码放在表格、状态、日志或错误对象中。已有账号的凭据编辑使用 Keep / Replace / Clear 明确操作，不能用空值隐式清除。

新密码两次匹配后才可计划。高级无密码选项独立说明后果。账号属性和集群共享影响在本页选择前提示；Review 再显示具体授权。检查期间保留输入和焦点，失败不会清空表单。

### Review

按数据库、角色、表、授权、配置分类，显示实际 Before → After。无变化项可以展开核对；未知事实不能伪装为 Missing。显示配置文件旧值、当前有效值、新值和环境覆盖情况，密码仅显示状态与来源。

可以回到对应字段编辑；任何影响数据库计划的修改都使旧验证和确认失效。保存偏好及路径只影响配置计划，独立重新检查文件。主动作 Apply changes 打开目标名称确认框，按钮默认不聚焦危险动作，Esc 返回 Review；必须精确匹配名称。Ready 只需要保存修改的连接信息时不出现数据库 Apply。

### Result

逐步显示 Completed / Running / Failed / Not attempted / Unknown；成功步骤始终保留。执行中禁止编辑影响目标的字段；取消请求只在安全边界生效，不能显示“全部回滚”。完成后分别显示数据库、writer、reader、配置结果。

认证失败使用同屏凭据控件修正，再执行只读验证，不重放创建/授权；其他失败提供 Recheck and review，从事实重新计算剩余计划。配置保存独立确认，失败可以改路径重试，不再执行数据库操作。退出全屏后向正常终端打印脱敏最终摘要及退出码含义，避免界面消失后没有结果可查。

## 3. 输入、焦点与原位刷新

鼠标可直接点击字段和页面，不必按 Tab 逐个经过。所有操作也必须可仅用键盘完成：

| 键位 | 行为 |
| --- | --- |
| Tab / Shift+Tab | 当前视觉顺序的下一/上一控件 |
| F1 | 打开键盘帮助；也有可点击的 Keys 按钮 |
| Enter | 激活已聚焦按钮；文本字段中不绑定全局执行 |
| Esc | 关闭当前弹窗；主界面请求退出时解释未保存/部分提交结果 |

第一版只使用鼠标点击和框架标准焦点导航，保留 F1 帮助，不实现 F2 检查、F6 分组或 F7/F8 切页。它们从必需验收中移除，浏览器原型曾演示不构成交付承诺。按钮按视觉顺序可由 Tab 到达，页导航始终可直接点击。快捷键只做已有动作入口，不绕过校验、禁用状态和确认。确认弹窗打开期间屏蔽后台切页与执行快捷键，焦点限制于弹窗，关闭后返回触发控件。方向键/Home/End 保持文本编辑含义，不注册 Ctrl/Alt 等全局字符组合抢占常见终端操作。F 键可能被浏览器或系统捕获，Demo 保留鼠标路径；真实终端仍需检查键盘/终端差异。

验证失败定位首个错误字段并在字段旁给出具体原因；若在其他页则先切到该页。修正输入后撤销旧错误提示。检查结果返回、样式更新和窗口变化不得把用户焦点移走；主动切页可聚焦该页首个可编辑字段或摘要。

字段改变立即标记 Dirty，撤销相关检查和确认；不按每个按键发数据库请求。首次加载自动检查，编辑后由 Check/Recheck 提交稳定的值。后台检查使用独立工作单元，不阻塞输入事件循环；结果附带配置快照标识，过时响应丢弃。界面刷新不重建正在输入的控件，不改变输入光标或覆盖文本。取消/异常最终必须恢复终端模式和光标。

与 terminal 的输入/输出交互交给 Textual；不在运行中的全屏内混用 click.prompt/print 或另一个 Rich Live。业务服务不依赖 Widget，不持有输入控件，仅接受明确配置与计划并返回结构化事实/事件。TUI 与 headless 共用检查、计划及执行，界面层不写第二套数据库规则。

## 4. 视觉约束

使用等宽终端字符和少量语义色：就绪为绿色、需注意为黄色、失败为红色；配套文字和符号。激活页和输入焦点有边框区别，禁用动作有解释。密码在只读摘要、预览及日志中只显示固定状态，不显示值或长度。正在编辑的隐藏输入允许框架按字符显示掩码，不要求隐藏实时掩码长度；不提供显示明文密码按钮。普通正文不过度加框，权限后果放在相关操作旁；当前字段、说明和错误尽量在同一视区。

不要求动画和持续高帧率。检查使用状态指示，执行用步骤进度，不显示不可靠 ETA。固定命令标题可见，目标库改变后标题及计划同步；超长 SQL/技术错误不要占据主页面，只提供脱敏诊断详情。

## 5. CLI 模式边界

`setup` 使用全屏 TUI，不再提供交互 plain 向导；普通下载命令的 --plain 保持不变。`--plain setup` 明确报参数冲突并提示 headless，不静默忽略。`-q/-v` 不删减必需表单、后果和确认；详细诊断可展开，不泄露秘密。非 TTY 或终端能力不足明确失败并提示 headless，不自动切换成会执行变更的模式。

headless 的凭据文件、只读检查/apply 授权、退出码和事件规则已完整定义于 [headless 契约](database-setup-headless.md)，不在 UI 中实现另一套解析器或保存路径。自动化永不保存 .env，由调用脚本负责。TUI/headless 共用 [主契约](database-setup.md)的服务和事件。

## 6. 验收补充

| 编号 | 条件 | 通过标准 |
| --- | --- | --- |
| UI01 | 键盘完成首次设置/已有配置编辑/失败恢复 | 鼠标直接定位，标准 Tab 导航和帮助可用且不绕过校验；无鼠标可达所有字段和动作，Tab 顺序合理，Enter 不误提交，Esc 不丢失已提交结果 |
| UI02 | 输入时刷新、慢检查、连续修改与窗口缩放 | 焦点/文本保留，过时结果不覆盖新配置，旧计划不可执行 |
| UI03 | 窄屏、长路径、错误与滚动 | 40/80/120 列能操作，关键差异可读，状态不依赖颜色 |
| UI04 | 确认取消、密码、后台失败、Ctrl+C/退出 | 无秘密泄漏，终端恢复，正常输出区有最终摘要；部分结果准确 |

设计定稿后、正式 UI 集成前，用 Textual 原生原型验证原位编辑与终端输入；浏览器 Demo 只验证布局和代表性流程，不能宣称 UI01–UI04 已通过。 headless 条件见 H01–H08。


### 可执行的人工与 UI 测试矩阵

- 支持基线为 Windows Terminal + WSL/Linux Python；至少在该环境实际完成首次设置、Ready 修改保存、部分失败修正三条路线。其他终端不因现代终端名称而宣称已验收；iTerm2/Warp/原生 Windows Python 不列为本版必过平台。
- UI03 的固定尺寸为 40×20、80×24、120×30（列×行），分别覆盖 Connection、Review 长差异、Result 和确认框。期间在 80×24 编辑字段时缩至 40×20 再放大，未提交内容和选区不丢失；长路径可滚动查看完整值，确认/取消可经键盘到达。
- 小于 40 列或 20 行显示 Resize required，不允许开始新的 Apply；恢复尺寸后草稿保留。若已有后台写入则按原执行边界收尾，不能因窗口缩小宣称回滚；中断入口仍有效。
- UI01/UI04：鼠标直接定位与纯键盘各走一次；在普通页、密码字段、确认框测试 Esc/Ctrl+C。确认框 Tab 不进入后台；文本字段 Enter 不执行计划；错误验证定位首个出错字段，异步正常完成不抢走正在编辑字段的焦点。
- UI02：可控 worker 延迟触发“旧检查晚于新配置返回”，断言旧结果不使 Apply 可用；检查中关闭界面，不留下会在 UI 消失后启动的新写动作。
- 自动 Textual 测试可覆盖状态/焦点/边界；人工记录终端、尺寸、操作、实际结果，不仅保存截图。秘密测试用标记密码，不使用真实凭据。
