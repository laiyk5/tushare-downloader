## 1. 边界与阅读流程 {#section-1}

[总体设计](overview.md)定义命令与参数、[结果统计](overview.md#section-8-2)、[退出码](overview.md#section-8-3)及[日志/报告存储](overview.md#section-7)。本文只说明如何呈现这些事实，不另定义一套计数。

用户流程：输入命令 → 阅读本地检查与请求范围 → 观察执行 → 阅读结果和异常范围 → 按需要查看完整报告或重新发起命令。无任务管理页面，不要求用户记住执行 ID。

## 2. 帮助与错误提示 {#section-2}

帮助优先展示命令用途和最短可用示例，再列参数及默认值来源。正式程序名使用 tushare-downloader；固定子命令缩写与参数清单引用[命令设计](overview.md#section-3-1)，不在本文维护第二份清单。

每个 API 的帮助明确只增型/可变型、时间范围/快照，以及 update 实际会请求什么。错误提示先给具体原因，再给可执行的下一步；默认不打印 Python 堆栈。不能把 API 错误描述成成功或把暂存描述成落库。

当前调用失败后提示重新执行完整命令或 fetch 指定失败范围；不提示不存在的恢复/查询命令。范围占位符以文字标明，避免用户误复制 shell 重定向语法。

## 3. 前后报告布局 {#section-3}

stdout/stderr 都优先人类阅读：stdout 为下载前后报告；stderr 为运行进度、重试摘要和错误。无终端 JSON 输出模式。--plain 使用无颜色、无 ANSI、无动态覆写的 ASCII 逐行文本；非 TTY 通道自动采用 plain。日志提供结构化信息。

下载前报告包含 API、命令目的、范围、更新语义、新鲜度规则、active/stale 行数、已取得/未查/失败/空响应分类、计划请求/跳过数量，以及跳过依据。不先宣称“完整”。--dry-run 到此结束，明确这是本地估计而非远端验证。

结束报告依次显示：

1. 总体结论：完成、完成但有待核实空响应、部分失败、提前停止或中断。
2. 分段结果：成功非空、成功空响应、失败、未尝试、因本地已有/新鲜而跳过。
3. 行结果：新增、源字段更新、未变、重新激活、新标 stale。
4. 持续失败及原因、空响应范围、尚未检查范围、提交未知范围。
5. 完整报告和日志路径，以及重新发起命令的示例。

长范围不刷屏：按分类合并相邻日期区间，默认每类展示最多 REPORT_MAX_ITEMS=20 条，并显示“另有 N 条，完整内容见文件”。终端省略只影响展示，完整 before.md/after.md 和事件日志不得漏项。快照用明确的范围名称。窄终端改用纵向键值布局，ID/路径可换行而不截断；不自动打开分页器或占用用户输入。

下载前分别列“用户指定范围”和“实际整块请求范围”，夹带日期不能被藏在摘要里。快照显示集合名称，不显示不适用的日期覆盖率。--dry-run 的标题使用“本地检查与计划”，不显示远端执行成功。

结果列表按需关注程度组织：先失败、提交未知和未尝试，再列待核实空响应，最后给普通成功明细。每类用连续日期区间合并，但失败原因不同的记录不能合并成一个含糊结果。完整 Markdown 报告保留所有明细与原因。

文件报告可直接阅读；终端显示完整路径供用户打开。不自动启动编辑器、分页器或要求按键继续。总体设计负责文件写入与失败语义，本文不另定义保存机制。

## 4. 进度、速率与 ETA {#section-4}

一个前台进度条显示：已处理分段/P、成功/失败/空、耗时、实际 HTTP 尝试速率、已确认输入行速率。失败计为已处理但不算成功；100% 只表示计划处理结束，最终仍可能部分失败。

ETA 用最近分段的实际墙钟耗时（包含限速和重试）估计，至少 5 段且 10 秒样本后展示近似值；样本不足、长退避或全局故障时显示“暂不可估计”。不为旧数据跳过或失败响应虚增吞吐。Rich 只负责渲染，不决定业务计数。

默认 TTY 最多 4 次/秒重绘，plain 每 PROGRESS_INTERVAL_SECONDS=5 秒一行。配置 PROGRESS=off 关闭周期进度；-q 隐藏常规进度和成功摘要，仍显示失败/空响应等需关注结论与报告路径；-v 展示分段详情，-vv 增加脱敏诊断。终结前停止刷新线程，避免摘要后继续出现进度。

可变型全表 update 分开显示“拉取/暂存”和“合并提交”阶段：分页取得数量可以前进，但已确认入库数量必须等事务提交。不能因所有网络请求结束就声称全部数据已保存。暂无足够样本时 ETA 显示“暂不可估计”；不能用网络阶段速度冒充整个合并阶段的 ETA。

异常时保持简短上下文：API、实际范围、当前尝试和错误原因；重试信息不能覆盖最终失败说明。布局只消费执行器快照，不为了刷新 UI 发 API 请求或写数据库。

## 5. 展示选项与环境 {#section-5}

持久偏好、默认值和配置优先级以[配置设计](overview.md#section-7)为准。展示选择不改变请求/写入行为，也不关闭关键文件日志。

| 选项或环境 | 展示效果 |
| --- | --- |
| 默认 TTY | Rich 进度与可读表格；stdout 为报告，stderr 为进度及诊断 |
| --plain / PLAIN=true | 两通道无颜色、无 ANSI、无动态覆写，采用 ASCII 装饰和逐行布局；中文正文仍保留 |
| 非 TTY | 对该通道自动使用 plain；stdout 重定向不必关闭仍在 TTY 的 stderr 进度 |
| NO_COLOR | 兼容为 plain 展示，不另设 --no-color 开关 |
| PROGRESS=off | 不显示周期进度；保留报告和诊断 |
| -q | 隐藏常规进度/成功摘要；需关注结论、报告路径以及显式查询/计划结果仍可读 |
| -v / -vv | 增加执行细节/脱敏诊断；不改变文件诊断级别 |

-q 与 -v 互斥。--plain 是格式选择，不等于静默。人类提示不承诺逐字符稳定的机器协议；自动化依赖退出码及文件日志。stdout/stderr 合并重定向时可显式 --plain。

## 6. 展示测试与复核 {#section-6}

以等价类划分和边界值选择代表场景，不声称有限例子证明全部输入：

| 维度 | 代表场景 |
| --- | --- |
| 输出环境 | TTY、非 TTY、两通道环境不同、plain、NO_COLOR、窄终端 |
| 结果 | 无需请求、全成功、成功空、部分失败、提前停止、中断、提交未知 |
| 列表长度 | 0、1、REPORT_MAX_ITEMS、REPORT_MAX_ITEMS+1、大量不连续范围 |
| ETA | 样本不足、刚达到条件、正常估计、长退避、全局故障、合并提交阶段 |
| 展示选项 | 默认、-q、-v、-vv、PROGRESS=off、plain 与详细程度组合 |
| 输出收尾 | 最终摘要后无进度刷新、输出管道关闭、报告保存失败 |

测试注入时钟和终端能力，检查信息与语义，不逐字符绑定 Rich 动画或瞬时时间。关键组合需覆盖，例如“非 TTY + 部分失败 + 超长范围”和“网络已结束但事务仍未提交”。主要布局可人工查看桌面与窄终端，测试无需连接真实 API。

统计守恒与事务正确性测试留在总体设计；块选择测试留在算法文档。本篇只验证这些事实没有被展示成另一种含义。
