# 当前设计验收标准

**适用设计：v0.3.0-draft.2；目标软件：v0.3.0。**
本文规定如何验收，不记录软件已经通过。当前没有在本文执行或勾选任何软件验收项目。
设计入口和修订历史见 [index](index.md)；实际执行证据应另存 development 下的 v0.3.0 验收记录，不覆盖 v0.1.0 历史记录。

## 1. 范围、判定和证据

本文是当前设计的验收门槛清单；各章节仍负责行为规范和测试用例细节。冲突必须先澄清正文，不能通过改测试或降低标准掩盖。
覆盖既有 daily_basic、stock_basic 和新增 daily、adj_factor、stk_limit、suspend_d，以及 fetch/refresh/update、list、init-db、clean。抽象类型的未来扩展、未注册 API 不属于本版实现门槛。
每个编号均为必需项，除明确标注的发布项或待决项。不通过、不执行、被跳过、预期失败都不能算通过。

| 验收阶段 | 通过条件 |
| --- | --- |
| 设计可实施 | 规范引用一致，测试预期可判定；实现相关歧义已澄清，发布待决事项明确登记 |
| 实现验收 | A–J 及 L 全部完成并有证据；未支持功能不能以旧版已验收代替 |
| 发布验收 | 实现验收通过，K 全部完成；已选 MIT 的声明和第三方分发义务落实 |

证据至少记录：验收编号、软件完整 commit SHA、采用的设计 commit SHA/版本、执行环境和依赖版本、命令/测试位置、预期与实际、退出码、脱敏产物路径或 CI 链接、结论。
同一测试或执行可以覆盖多个编号，不要求每个编号新建脚本。沿用既有有意义测试，不机械重复实现。
六种终端模式比较同一初始数据库和输入下的结果语义；忽略运行 ID、路径、时间戳、耗时等合理差异，不要求报告字节相同。
旧版证据只可复用于未改变且有明确变更影响分析的环境/部署事实；候选软件仍需运行完整回归。变更后的能力必须有当前实现证据。

## 2. 检查中确认的边界与未决项

1. 只增型快照、可变型时间范围等尚无注册 API；无需为了满足“类型笛卡尔积”添加产品功能。现有纯算法的边界测试仍保留。
2. 程序自有提示/报告使用英文；API 原始错误或数据可以是中文，但须有英文上下文且安全转义。
3. 日历模式失败不能自动切换 basic/off；basic 默认不需要外部日历。日历内容真实与永久正确不是可证明的验收目标。
4. 不把“日历获取成功”误记为数据下载成功，不把“快照子请求成功”误记为已提交。
5. `report.md` 是计划与最终结果记录，不是实时进度文件；强制终止可留下未完成报告，不能保证必然产生最终摘要。
6. MIT 已由维护者选定；根 LICENSE、元数据和 README 必须一致。第三方材料保留其许可，数据授权不由代码许可授予。选择完成不等于最终分发检查完成。
7. 跨日志分片连续监看便利入口移入后续 backlog，不属于 v0.2.0 范围。当前最低承诺是分片完整保留、最终报告列出全部实际分片、明确单文件 tail 的限制；不得宣称已实现自动跟随。增加该能力需先明确规范再验收。
8. 当前 HTML demo 是较早的模拟布局。它可以辅助评审，但不能替代真实 Rich 终端验证；若保留旧版，必须醒目标注差异，不能伪称与当前实现完全一致。
