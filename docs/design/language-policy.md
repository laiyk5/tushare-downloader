# 中文与英文适用范围

版本与状态见 [设计入口](index.md)。本章是 v0.3.0 的语言规范。

## 按读者与用途选择语言

| 内容 | 语言 | 边界 |
| --- | --- | --- |
| CLI 帮助、错误上下文、进度、程序自有日志、生成报告 | 英文 | Rich、plain、quiet、verbose 使用同一套术语 |
| README、用户指南、API/CLI reference、运维指南 | 英文 | 聚焦已发布能力，不混入开发 reminder |
| 代码标识符、注释、docstring、测试名称与断言说明 | 英文 | 测试输入可以包含中文，以验证真实数据与 Unicode |
| 配置模板注释、脚本帮助、构建和 CI 提示 | 英文 | 键名保持兼容；shell 示例默认 Bash |
| 设计正文、设计待办、内部决策与验收分析 | 中文 | API 名、代码、字段、命令与统一技术术语保留原样 |
| 开发环境、测试方法、贡献和发布操作指南 | 英文 | 面向贡献者的可执行教程；与中文验收分析区分 |
| 设计 Demo 的说明与控制按钮 | 中文 | 模拟终端、帮助和报告内容必须英文 |
| 新 Git commit、PR 标题与摘要、面向用户的 release notes | 英文 | 设计讨论可中文；历史提交及标签不改写 |
| 导航 | 按目标内容语言 | User guide / Reference / Operations / Development 使用英文；设计与验收分析入口使用中文 |

不建立双语镜像或运行时语言切换。英文产品文档可链接中文设计，但必须标明其语言和用途；用户不应依赖设计文档才能完成常规操作。

## 原文例外

API 返回的名称、数据值、错误原文和第三方引用保留原文，不翻译或修改存入 raw 表的值。错误前加英文上下文；敏感信息脱敏、控制字符安全转义仍执行既有规则。正式许可证保留原文。路径和用户输入也不因语言规则改写。

统一使用 fetch / refresh / update、append-only / mutable、snapshot / time-range、skipped / filtered / empty / failed / stale。中文设计沿用“只增型”“可变型”“请求块”“核对”，不要将只增型描述为绝对不可修改。

## 实施审计

先按上表列出当前文件的用途与语言，再处理不一致项：开发教程及其导航、配置/脚本注释、帮助与错误分支、报告模板与 Demo 模拟输出。中文 backlog、设计和验收分析无需整体翻译。

通过文本扫描定位候选，再人工确认原文例外；禁止把“出现汉字”直接当失败或全库自动替换。检查发布安装包的真实 CLI，以及 Zensical 构建后的导航和页面。既有发布记录作为历史证据保留，不为满足新规则改写旧结论。
