# 开发文档与版本产物目录

归属 [当前设计](index.md)，对应 [BL-017](../development/backlog/index.md#bl-017)。本页规定下一轮迁移的目标与测试条件，尚未执行文件迁移。目标是按版本归集证据，并避免 patch 在 development 根目录持续平铺。

## 1. 目录契约

```text
docs/development/
├── setup.md / testing.md / benchmarks.md / documentation.md
├── licensing.md
├── backlog/                 # 跨版本的事项索引及四状态正文
└── releases/
    ├── index.md             # 系列索引
    ├── legacy-paths.json    # 旧路径到新路径的固定映射
    ├── v0.1/
    │   ├── index.md
    │   └── v0.1.0/...
    ├── v0.2/
    │   ├── index.md
    │   └── v0.2.0/...
    └── v0.3/
        ├── index.md
        ├── v0.3.0/
        │   ├── index.md
        │   ├── release-v0.3.0.md
        │   ├── acceptance-index-v0.3.0.md
        │   ├── benchmark-v0.3.0.md
        │   ├── benchmark-v0.3.0-api/...
        │   └── terminal-v0.3.0/...
        └── v0.3.1/...       # 仅展示未来 patch 规则，不预建空目录
```

每个软件版本在 `releases/v<major>.<minor>/v<major>.<minor>.<patch>/` 下集中存放产物。系列目录只在出现实际内容时创建；新 patch 只增加对应系列内的目录，不增加 development 或 releases 下的同级系列。保留现有产物基名和其内部成组目录，迁移时不同时重命名所有证据文件。

系列索引按版本从新到旧列出发布、候选或历史记录状态和入口。单版本 index 列出设计与软件 SHA、验收、基准、终端及其他证据，注明每项实际测量版本与复用边界。文档目录中的版本号不是已发布声明：发布前可归集到拟定版本，但索引明确未发布；版本未确定的试验留在既有被忽略的本地产物位置，选定后才收录证据。

跨版本复用证据只保留原始归属的一份正文，后来版本以链接引用并说明适用范围，不复制或改名冒充本版实测。一个 patch 下的候选提交由证据文件记录 SHA，不为每个 commit 新建一层发布目录。不同原始样本如需同名文件，使用执行标识或既有子目录隔离，禁止覆盖。

## 2. 迁移范围与归属

| 当前内容 | 目标 |
| --- | --- |
| setup、testing、benchmarks、documentation、licensing 等持续维护指南 | 保留 development 下；内容仍按读者身份组织 |
| backlog 索引、四状态文件及既有兼容入口 | 保持当前位置，编号不变 |
| 明确标为 v0.2.0/v0.3.0 的验收、发布、基准、截图、JSON/JSONL/ANSI/TXT 等证据 | 连同成组子目录迁至对应系列／patch 下 |
| design-v0.2.0-finalization.md | 归入 v0.2/v0.2.0，保留其“设计定稿记录”性质及独立设计 SHA |
| acceptance.md、benchmark-baseline.md、output-examples.md、verification.md 等无版本号历史文件 | 先按正文及 Git 来源核实软件归属，再登记逐文件映射，不能一律猜作 v0.1.0 |
| benchmark.md 等旧教程或兼容入口 | 判断是否仍为指南／跳转页；保留或归并至长期指南，不能因名称相近当作基准证据 |

迁移前建立完整清单，包含每个旧路径、目标路径、来源版本及旧文件 SHA-256。出现归属不明确的文件，应调查其历史并写明结论；确实跨版本且不能合理归入一个 patch 的记录才放 `releases/shared/`，索引明确覆盖范围，不把 shared 当未分类收纳处。未解决归属的条目阻止该文件迁移及整项签核。

本轮覆盖仓库内 development 的历史版本产物，不移动用户 logs/reports、数据库备份或被忽略的本地实验数据，不改动 docs/design 的历史标签或复制每版设计正文。

## 3. 证据完整性与引用

JSON、JSONL、ANSI、TXT、图片和其他原始附件逐字节保留。其内部记录的本机路径、旧版本路径、SHA 和时间是历史事实，不批量替换；需要解释时在新版本索引或迁移映射中补充。

Markdown 的业务叙述、测量结果、验收结论和版本身份保持原意，只允许为迁移修正相对链接或增加明确标注的迁移说明。迁移清单记录修改前后哈希及允许的链接变更；不能同时修订旧结论却称作纯移动。原始全文仍可从旧标签／提交追溯。

同步所有当前站内引用、README 发布入口、Zensical 导航、脚本中已选定证据路径和 .gitattributes 的 ANSI 字节保护路径。构建工作目录和生产日志配置不因文档迁移改变；不强迫 benchmark 改写其本地产物默认目录。

## 4. 旧链接兼容

不在 development 源目录保留每个旧文件的跳转 Markdown，否则仍然平铺。用一个固定映射清单，在站点构建后、本地检查和上传产物前生成兼容产物：

- 旧 Markdown 网页地址生成轻量跳转页，使用新页面项目子路径地址；保留 query/hash，支持直接打开旧锚点。JavaScript 不可用时提供清晰的新页面链接，不以服务器 301 为前提。
- 旧 JSON、图片等附件 URL 在构建目录生成原字节兼容副本；仓库源码只保留新位置的原件，避免把重定向 HTML 当作数据文件返回。
- 新规范导航只指向新位置；旧地址作为兼容，不加入主导航或新搜索索引。保持原 Markdown 标题锚点，确需变更则显式保留旧锚点。
- 历史 GitHub blob 路径不能依赖 Pages 重定向；已有固定标签／SHA 链接不变，对 main 的当前引用更新为新路径，迁移清单用于查找旧路径。不能宣称所有外部 GitHub 书签都能自动跳转。

兼容逻辑采用一个小型本地构建脚本读取映射，不增加文档引擎或第三方重定向服务。映射只允许站点内相对路径，校验冲突、缺少目标和越出 site 的路径；错误使构建失败，不覆盖无关产物。

实施时将“严格构建 → 生成兼容产物 → 链接／字节检查”作为同一文档构建流程，记录本地预览方法。必要发布时 CI 调用同一流程并上传同一产物；本次设计和本地验证不触发 GitHub workflow。兼容副本保留至未来明确评审其移除影响，不能按 patch 发布自动过期。

## 5. 迁移顺序和回退

1. 核对当前文件清单、版本归属、内部引用与旧公开地址，先形成唯一映射并检测目标重名。
2. 在独立本地分支移动文件、修正允许的引用、补齐三级索引和构建兼容规则；定稿前不执行本步骤。
3. 检查字节及链接、构建本地站点并验证旧新入口；review diff 只包含迁移和必要引用／构建调整。
4. 本地完成后等待必要同步或发布时再推送。发布失败不得把未部署站点算已兼容；可以回退整个文档迁移提交，不改软件或数据库。

如果工作区有不属于本次的修改，保留并隔离；恢复仅针对本次变更，不用 reset --hard 或递归清空目录。迁移工具报错时先核对清单中实际完成的移动再继续，不盲目重复或覆盖。

## 6. 先于迁移确定的测试条件

| 编号 | 条件 | 预期 |
| --- | --- | --- |
| DL01 | 当前文件清单及目标映射 | 每个版本产物有唯一归属和目标，无遗漏、重名或未解释的 shared 项 |
| DL02 | v0.3.0、v0.3.1、v0.4.0 的目录夹具 | 前两者位于同一 v0.3 系列，后者位于 v0.4；development 根目录不随 patch 增加目录 |
| DL03 | 原始附件迁移、Markdown 链接调整 | 原始附件 SHA-256 完全相同；Markdown 差异仅限登记的链接／迁移说明，历史数值与 SHA 不改 |
| DL04 | 成组样本引用、跨版本复用、ANSI 文件 | 所有本地引用可解析；复用不复制冒充；新路径保持字节属性 |
| DL05 | 旧页面地址、query/hash、禁用 JS 后备 | 旧路径可找到新页，启用跳转时片段与查询保留；后备链接可用，无跳转循环 |
| DL06 | 旧附件 URL、新规范路径、项目子路径 | 两份构建附件字节一致；不把 HTML 返回为 JSON；目录部署与根路径本地夹具均有效 |
| DL07 | 缺目标、重复别名、路径越界、覆盖现有非别名产物 | 构建失败，不写出 site 范围外或覆盖无关内容 |
| DL08 | 导航、搜索及本地预览 | 新索引便于按系列和 patch 查找，旧别名不重复进入搜索；严格构建及完整链接检查通过 |
| DL09 | 实际发布与回退 | 必要发布阶段验证线上旧新入口与附件；复用既有同产物部署与 revert 机制须说明未变化范围，未发布时记录未执行 |

原始数据不变的承诺用哈希验证，链接兼容用本地站点夹具和人工浏览验证，不能仅凭 git diff --stat 或严格构建成功签核。DL09 属于发布阶段，不能为推进本地工作提前触发远端部署。
