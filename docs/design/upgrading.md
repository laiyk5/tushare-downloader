# 升级支持与用户指南设计

当前为 v0.4.0 / revision 6 定稿。本文负责来源支持矩阵、用户操作与恢复；[迁移契约](database-migrations.md)负责执行语义。首条正式路线 v0.3.0 → v0.4.0，后者尚未发布；不追补 v0.2.0 → v0.3.0 指南，不改写旧验收。

## 1. 支持范围

| 来源 | 发布时的要求 |
| --- | --- |
| 同 minor 旧 patch | 明确兼容性及必要动作；有结构差异时覆盖代表状态 |
| 上一个已发布 minor | 以其最新发布 patch 的真实结构验证；声明支持范围内由当前 setup 连续迁移，无需安装每个中间软件版本 |
| 上一个已发布 major | 从其最后维护 minor 最新 patch 给出路线；0.x 尚无上一 major 时不适用 |
| 更早或非标准库 | 列出明确支持路径，否则拒绝；确需指定中间软件时说明，不宣称任意未知版本直升 |

软件来源矩阵与数据库结构支持分开：同一结构可被多个软件版本使用，不能按软件版本推断需不需要 DDL。当前已验证来源是 v0.3.0 原始六表和已知 v0.4.0 候选结构；更早版本不新增真实演练要求。跨版本执行使用已有 schema_version/specs，不增加软件版本列。

## 2. 当前升级差异

suspend_d 原 spec 1 / Dataset schema 1.0.0 通过 setup 迁移到 spec 2 / 2.0.0；其他五表不变，内部 schema_version 仍为 1。已经迁移的候选库不重复执行。所有原数据（含 stale）、database_id、管理字段及其他 API 观察保留；旧 suspend_d spec 1 块记录不作为 spec 2 的可复用覆盖，后续主动 fetch 正常替换对应块。

缺少独立 API 表由 setup/init-db 按当前契约创建，不要求删库；已登记却缺失的表属于漂移。init-db 不能代替旧表结构迁移。账号授权按差异且经确认才补齐，迁移本身不重复 GRANT、不更改角色密码/属性；已有合规 ACL 保持。读取需 meta 权限的用户按标准访问规则补齐，不能保证所有旧 reader 无操作即可用 Inspect。

原 PG* 配置优先级保持，普通 DATABASE_URL 仍不支持；不新增必填配置、不覆盖 .env、不 source 配置文件。新日志写 LOG_DIR/<command>/，旧日志和报告不搬移；迁移新日志属于 setup。代码访问开发/生产的纪律见迁移章，不将验收候选连接生产。

## 3. 英文用户指南交付

实施时同步现有 operations/upgrading.md、guide/database-setup.md、guide/migrate-suspend-d.md、reference/cli.md、reference/schema.md 的迁移链接与数据库维护入口。保留既有指南 URL，改为 setup 步骤，避免用户书签失效；历史版本记录不改命令。用户页只描述届时已实现功能，不夹开发待办。

指南默认 Bash，明确以下顺序：

1. 确认来源版本、正式目标版本和实际连接，保留配置/本地修改；停止本人的其他 writer，不停止 PostgreSQL 服务。
2. 用正式工具备份原库并准备独立恢复方法。pg_dump/psql 不读取项目 .env，不能 source .env；非秘密 PG* 显式设置，密码用受保护 pgpass 或交互。不覆盖已有备份文件。
3. 正式发布后更新至对应标签并同步锁定依赖；目录改变时检查相对配置和日志路径。候选演练在开发库执行同样的升级步骤。
4. 运行 setup 检查身份和全部计划，确认后升级；自动化先运行 setup --headless，再显式授权 apply 和真实库名。备份可读不等于恢复验证通过；升级前有阻塞则保留原库并停止。
5. 核对数据库身份、已安装/目标契约、原数据/观察与 reader 读取，检查迁移结果；list 只证明接口登记。主动决定是否按原范围 fetch，不把重下载合并为 setup 的自动动作。

指南需说明 suspend_d 下游键加入 suspend_type；不提供有损合并视图来维持旧一股票一天一行假设。大表不为验收界面全表计数；独立测试夹具可完整比较以证明无损。

## 4. 失败恢复与降级

按步事务：成功步骤保留、当前失败回滚、后续未执行；重跑 setup 读取事实重新规划。提交应答不明按 Unknown 处理，先只读复核，不盲目重发。配置保存失败不重跑数据库操作。

不提供自动 down migration。suspend_d 缩回旧键会再次冲突，不在原库回退。需回退时恢复迁移前备份至另一名称数据库，核对旧结构、身份、数据和权限后再由用户切换；原库保留。明确备份后新数据不在备份中。旧 v0.3.0 软件只能使用兼容旧结构；不能根据同 major 就假设可读新结构。

备份示例使用 pg_dump --format=custom，恢复用 pg_restore --exit-on-error --single-transaction 到预建独立库；所需角色提前存在。生产操作使用正式代码和用户授权，文档不是代理现在升级生产的许可。
