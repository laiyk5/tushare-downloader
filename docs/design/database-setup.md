# 数据库设置向导

归属 [当前设计](index.md)，BL-018，v0.4.0 / revision 2 定稿，尚未实施。关联 BL-011 升级、BL-013 用户访问，提供统一入口，不取代其权限及结构契约。

## 1. 范围与入口

拟新增 tushare-downloader setup，作为可选交互向导，不设缩写。沿用全局 -c 配置路径、--plain、-q/-v；没有默认自动执行或 --yes。setup --help 不需要配置、数据库或凭据。stdin 不是交互终端时退出 2，提示使用现有非交互操作/人工 SQL；不无限等待输入。plain 仍可交互但无 ANSI/重绘；quiet 仍保留问题、计划、确认与结果，verbose 不显示秘密。

| 选择 | 当前交付内容 |
| --- | --- |
| Configure connection | 收集、测试连接；用户选择是否保存下载器配置；不要求管理员，不写数据库 |
| Initialize database | 检查/创建数据库及 writer/reader、调用既有初始化能力、配置权限并验证 |
| Check database upgrade | 识别版本与结构，解释无需迁移、缺失独立 API 表、明确受支持路径或不支持；当前没有已有表结构迁移执行器 |

本版支持当前六表标准 v0.3.0 库和未发布 v0.4.0 候选库：已有表无需迁移；新增独立 API 表通过 init-db。未知版本、已有结构漂移不自动修复。setup 不安装 PostgreSQL/驱动、不修改 pg_hba.conf/防火墙/服务、不升级 PostgreSQL 主版本、不更新 Python 软件包、不创建研究视图、不备份整个数据库或自动恢复。

## 2. 交互顺序与权限切换

收集意图与连接 → 只读检查 → 展示操作计划 → 用户确认具体变更 → 执行 → 独立连接验证 → 可选保存配置 → 总结。

1. 收集 host/port/database、SSL 设置与角色名，默认沿用现有配置，首次推荐 tushare、tushare_writer、tushare_reader。密码隐藏输入，不从管理员连接推导日常 writer。无效原配置可以进入修正界面，不能在向导启动前因下载 Token/无关参数错误而退出。
2. 日常连接使用目标账号；需要建库/角色/补权时另询问管理员连接及维护数据库（默认 postgres，可改）。明确显示实际 server/database/current_user 和目标名称，不打印含密码 DSN。管理员连接不自动写回配置。
3. 无管理员凭据时可选“生成操作脚本”。有读取权限则生成针对已检查状态的脚本；完全无法检查时生成需管理员先检查的模板，标 Unverified，不冒称可直接幂等执行。
4. 初始化后以真实 writer 连接调用 Store 的初始化/校验能力，确保对象创建者正确。以 reader 的真实登录验证 SELECT，并检查有效权限和所有权；不以管理员 SET ROLE 代替登录验证。若现有认证方式无需密码且实际登录成功，也可通过；没有可用认证方式时记录 verification not performed，不显示全部完成。

管理员可能有权创建角色但没有创建数据库或切换到目标所有者的权限，需逐项检查，不只看 superuser 标志。既有角色必须展示属性、继承和对象归属；不重置密码、不接管外部同名库/表、不授予 reader 写权限、不自动 REVOKE 其他应用或 PUBLIC 权限。符合契约的已有对象可复用，冲突时给出下一步，不能自动扩大管理员操作范围。

### 2.1 数据库与角色的复用判定

| 检查到的对象 | 当前允许的动作 |
| --- | --- |
| 目标数据库不存在 | 确认后新建，owner 为已验证 writer；再按 writer 身份初始化 |
| 有合法 application_id/database_id 和受支持结构的受管理库 | 复用原身份和 owner，不迁移所有权；只计划已支持的增表/补权 |
| 既有空库 | 仅当 owner 已是选定 writer，且无 raw/meta、无模板标准系统对象之外的用户表/视图/函数/schema（空 public 允许）时，明确列出 Adopt empty database 并确认后初始化 |
| 无有效身份的非空库、占用 raw/meta、非 writer 所有的空库 | Blocked；提示选用其他数据库或由管理员手工整理，不自动接管、清空或 ALTER OWNER |
| 身份存在但结构/版本未知或漂移 | Blocked；不根据缺列等现象自动修复 |

标准受管理库需校验 writer 对受管理对象的实际所有权/初始化能力，不能只因用户名相同就通过。用户自建 analysis 对象不阻止已受管理库的正常复用；“空库”规则只用于首次接管，不能误用于升级检查。

角色名在整个 PostgreSQL 实例内共享。新角色须符合数据访问章的属性；既有角色检查属性、有效继承/SET ROLE 通路以及可见依赖，在计划中显示 Existing cluster-wide role，要求用户确认复用。无法证明符合条件就 Blocked/Needs administrator review，不修改属性、密码、成员关系或对象所有权。本版不保证自动枚举所有其他数据库内的依赖；明确显示检查范围，不以“本库无对象”推断角色未被其他应用使用。

已有 reader 的新增授权仅限本次目标库的 USAGE/SELECT 和真实 writer 的 raw 默认权限，明确提示该角色的其他使用者也会获得目标库读取权。writer 与 reader 必须不同，且选定 reader 不可为管理员角色。需要建库/初始化的模式要求 writer 非超级用户并符合既有部署契约；有冲突时允许重新选择账号或取消，不能强行降权已有共享角色。

## 3. 计划与确认

计划按 Database / Roles / Tables / Grants / Configuration 分组；每项标 Create、Reuse、Grant、No change、Blocked。显示数据库名称、现有 database_id（如果有）、角色、将变更的权限、配置绝对路径以及不可整体回滚的步骤。所有 SQL 标识符安全引用，绝不把用户输入拼接成 shell 命令；控制字符/不支持的名称明确拒绝，不静默截断。

纯检查无需确认；产生变更时先展示完整差异，默认不执行。输入目标数据库名确认数据库操作；配置保存另外展示脱敏差异并确认。执行前重新检查关键对象与权限：若已与计划不同，停止并重新规划，不沿用过时确认。执行中遇到同名创建竞争或数据库身份变化，停止，不把新出现的对象自动视为本向导创建。

英文呈现示意（非产品运行证据）：

```text
Database setup · tushare

Database       Reuse      Existing managed database
Writer         Reuse      tushare_writer
Tables         No change  6 compatible tables
Reader         Grant      SELECT on 2 metadata tables
Migration      No change  No database migration required
Configuration  Keep       /home/user/project/.env

Apply these database changes? Type the database name:
```

不使用下载 ETA 或请求速率；执行中只显示当前步骤及已完成/失败项。最终分别给出 database、writer、reader、configuration 的结果，不用单个 Success 隐藏未验证或未保存。用户拒绝变更属于 Cancelled，退出 0；错误/验证失败退出 1，参数或非交互使用错误退出 2，writer 锁冲突沿用 3，Ctrl+C 为 130。脚本成功导出可退出 0，但必须显示 Script generated — database changes not applied。

## 4. 执行边界、失败和再次运行

创建数据库是单独步骤，不能放进普通事务。角色创建/授权在各自可用的事务边界处理；目标库的表初始化沿用 writer 锁和现有单事务增表。授权只应用本次已确认且可证明必要的差异；默认权限绑定真实对象创建者。禁止把整个向导描述为原子事务。

每步记住当前进程中已确认的结果。失败后保留已成功创建对象，不自动 DROP 数据库/角色来“回滚”；显示已经完成、失败、未执行和结果未知的步骤。COMMIT/建库确认丢失时不盲目重试写入，可重新连接只读检查事实；无法确认则保留 Unknown。后续重新运行从数据库事实检查，无 resume、持久任务或恢复账本。

数据库初始化完成但配置保存失败，应显示数据库已经可用及重新配置方法；不能撤销数据库。新角色因后续失败留下时，明确告知管理员，不擅自删除可能已被使用的角色。重跑不重复授予已有权限、不重新设置已有密码、不改变 database_id 或已有数据。

在线向导仅进行无副作用 SELECT 和权限/所有权检查来验证 reader，不在真实用户表上试 INSERT/DELETE，也不把 BEGIN/ROLLBACK 当成消除任意触发器副作用的方法。实际写入拒绝测试仅在独立数据库夹具执行。无法排除继承或自定义提权通路时标需管理员检查，不作完全只读保证。

### 4.1 等待预算

连接复用 CONNECT_TIMEOUT_SECONDS（默认 10 秒）；本版向导限定单主机连接，多个主机/地址回退不能各自重新取得整份预算。只读检查及验证每个阶段复用 INSPECT_TIMEOUT（默认 5s）。新增 SETUP_STEP_TIMEOUT=60s（正时长，最多 10m），用于每个数据库变更步骤的总预算，包含事务提交；锁等待最多 min(5s, 剩余步骤预算)。权限/建库/初始化分别计步，不让每条 SQL 重置总预算。人工输入等待不计入数据库执行预算，用户可随时取消。

服务端 statement_timeout/lock_timeout 按剩余预算设置，并需要可取消的客户端期限覆盖连接/DNS、网络失联及提交等待，不能只设置 statement_timeout 就声称客户端不会卡住。期限到达停止该步骤并关闭/取消连接，退出失败路径；只读步骤标 Timed out，变更只有确认回滚/取消完成才能称未应用，否则标 Unknown。

Unknown 后最多进行一轮新的、有独立检查预算的只读重连核实，禁止自动重发变更。即使服务端取消确认延迟也必须结束客户端等待，显示结果未知；不把客户端超时当成服务端绝对停止证明。预算值进入配置参考的 Local database setup 分组，不增加 CLI 超时选项；无效值在执行前提示修正。

## 5. 配置与脚本产物

密码默认只在内存中用于此次连接。管理员和 reader 密码不保存；writer 密码仅在用户明确选择保存到下载器配置后写入所选文件，计划/预览一律遮蔽。文件权限按支持的 WSL/Linux 环境限制到当前用户；失败则不宣称保存成功。不声称能保证 Python 字符串内存被彻底擦除。

唯一保存形式为现有 PGHOST、PGPORT、PGDATABASE、PGUSER、PGPASSWORD、PGSSLMODE；不新增 DATABASE_URL 支持，也不把 TEST_DATABASE_URL/BENCH_DATABASE_URL 用于日常连接。此前“沿用 DATABASE_URL/PG*”的描述与实现不符，本次纠正。检测到普通 DATABASE_URL 时显示 Unsupported connection key — not used，值脱敏且原文保留；不自行解释/转换 URL，用户按提示填写 PG*。仅有 DATABASE_URL 时不能把默认 localhost 连接结果当作该 URL 已验证。

保存时按键显示 file/environment/default 的来源，环境仍逐键覆盖文件。用户可选择保存但标 Saved, overridden by environment，或取消保存；向导不修改父进程环境、不删除冲突环境变量。确认中的连接是用户本次选定的临时连接，落盘后另按实际加载优先级重新求值，只有与已验证连接一致才能显示 Effective configuration verified。密码来源/是否变更可显示，密码值不能显示。

已有 PG* 行原位替换，缺少的键加入 Database 分组；仅修改确认的键，保留行尾注释、其他分组、未知键和普通 DATABASE_URL。重复连接键、无法无损解析的引号/多行连接值、符号链接或非普通文件拒绝自动覆盖，提供保存到新文件选项；不能用“最后一个值有效”掩盖歧义。-c 指定的新文件允许向导创建，即使普通下载命令对不存在的 -c 文件报错；该例外仅属于 setup。全新文件采用 PG* 分组，不写测试/管理员/reader 凭据。

配置保存使用同目录临时文件、受限权限和原子替换；保存前比对读取时内容，发现被其他进程改过就重新展示差异。临时文件失败时清理，不生成含秘密的备份副本。用户可选择不保存，只保留无密码连接说明。

SQL/psql 脚本只在用户选定路径后导出，文件存在时不静默覆盖；默认受限权限。脚本含目标说明、各步骤执行账号、停止于错误的设置、执行前检查与执行后验证，不含密码或密码字面量。密码由管理员通过交互式 psql 密码设置完成；脚本生成器必须正确处理 SQL 引用和 psql 特殊语法，无法安全表达的输入拒绝导出。

脚本分清“管理员建库/角色 → writer 初始化 → 管理员授权 → reader 验证”；表 DDL 不另复制一套，文档指引仍调用 init-db。脚本不可在同一个包裹事务中执行 CREATE DATABASE；导出不是执行许可或验证证据。无需为了脚本离线运行引入通用迁移脚本框架。

### 5.1 导出包的固定结构

导出目标是用户选定的新目录（已存在则要求另选），目录 0700、文件 0600；无需文件可省略，但 README 必须说明。所有内容成功写入临时目录后再发布为目标目录；失败不能留下看似完整的包。

| 文件 | 类型与职责 |
| --- | --- |
| README.md | 英文目标/检查时间/Verified 或 Unverified、操作计划、权限前提、按顺序执行方法、密码输入与中途失败处理 |
| 01-admin.sql | psql 文件：管理员身份/目标/已有角色属性前置检查、必要角色创建、交互式密码设置、独立建库步骤 |
| 02-initialize.sh | Bash 文件：显式通过现有 -c 配置调用 init-db；只在需初始化/增表时提供，不复制表 DDL |
| 03-grants.sql | psql 文件：连接目标库并重检身份/owner，应用确认的 USAGE/SELECT/默认权限 |
| 04-reader-check.sql | psql 文件：以 reader 登录运行只读验证；拒绝管理员身份充当 reader 验证 |

README 给出分别使用管理员/writer/reader 连接的命令，不提供以管理员一路执行的总脚本。psql 使用停止于错误的设置和有限等待，建库禁止被单个全局事务包裹；Bash 使用明确的失败退出并检查配置，不 source 任意 .env。命令中的路径/名称分别使用对应语法安全转义，禁止把 SQL 引用当作 Bash 引用。

直接执行和导出共用相同的已检查操作计划、前置条件及权限集合；分别渲染 psycopg 与 SQL/psql 表达式，不建立第二套规则引擎。导出记录预期对象状态，执行时前置条件不符就停止并重新生成；已部分执行的包不承诺原样幂等重跑。Unverified 包先要求管理员完成只读检查并返回向导重新生成可应用包，不包含可直接执行的创建/授权步骤。导出包不是可供 setup 重新加载执行的任务文件。

setup 不使用下载 Reporter，不自动生成 reports/<run> 或 logs/setup 目录。当前交互摘要足够，用户可明确导出无秘密计划/脚本；下载日志规范只适用于下载命令。程序错误输出不含连接秘密、异常 locals 或密码 SQL。

## 6. 升级入口的扩展边界

当前升级检查输出 No database migration required，或说明需要现有 init-db 增补独立表/权限。检查本身只读；用户选择应用时重新走计划及确认。未知来源只给诊断和已支持路线，不调用自动 schema diff 修复。

未来某次确需结构迁移，应先定稿该来源→目标的具体设计和测试，再接入相同向导；迁移服务须可由非交互入口调用。每条路径定义身份/版本前置条件、变更、事务/锁预算、停写要求、备份/恢复、失败/中断/重入以及旧软件兼容。本版不创建空 migration 引擎、不声称能自动升级任意未来 schema，也不提供尚无实现内容的 migrate 命令。

## 7. 开发分工

向导只组织提示与用户选择；连接检查、计划计算、计划执行和验证是可独立测试的函数，返回结构化事实供呈现。复用既有初始化、结构验证、连接解析及访问契约；不得在 CLI 中重写一套建表或版本判定逻辑。计划只在内存存在，必要时转成脱敏展示/脚本，不成为持久执行系统。

建议按检查/无变更路线 → 配置保存 → 创建/授权 → 脚本导出依赖顺序实施，每部分都先有失败测试再写代码。对应开发环境及隔离要求见 [开发指南](../development/setup.md) 和 [测试指南](../development/testing.md)。新用户指南仅在命令实现并验证后补入 setup 操作步骤；现有手动安装、授权和 init-db 继续有效。

| DBW08 | 隐藏输入、特殊字符密码/标识符、异常、脚本已有路径 | 无秘密泄露/SQL 或 psql 注入；无覆盖；导出不执行，不另维护表 DDL |
| DBW09 | 脚本在独立集群按账号步骤执行、与直接路线对照 | 标准环境最终对象/权限等价；密码只交互输入；未验证模板明确标记 |
| DBW10 | 真实 v0.3.0 升级检查与 reader 缺权、已有研究对象 | 原库原数据原权限保持；仅确认后补权；不重建、不覆盖用户对象 |
| DBW11 | 40/80/120 列交互、Ctrl+C、默认拒绝与结果部分成功 | 英文步骤清晰、完整目标可读、状态不靠颜色，真实终端人工确认 |

本节是测试条件而非已通过记录。结构兼容复用 SC、权限复用 DA；向导新增测试集中于编排与边界。最终软件回归不能沿用未包含 setup 的旧候选结论。

### 补充定稿检查用例

- DBW02：增加 writer-owned 空库、其他 owner 空库、未登记非空库、标准库含 analysis、共享角色/继承写角色、writer=reader，逐项核对上表允许与拒绝。
- DBW05：增加连接/DNS 不返回、SQL 锁等待、建库/COMMIT 超时及核实再次超时；断言客户端预算有界、最多一轮核实、无重复变更。
- DBW07：增加仅 DATABASE_URL、PG* 与 URL 并存、逐键环境覆盖、缺失 -c 目标、新文件/符号链接/重复键/注释；断言保存内容与真实有效配置分开呈现。
- DBW09：核对固定包结构、各账号及语法、旧计划拒绝、Unverified 包不可直接写入、导出失败无完整包，以及与直接计划的操作集合一致。
